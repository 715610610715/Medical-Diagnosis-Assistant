# 医疗诊断辅助系统 · 产品需求文档（PRD）

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 医疗诊断辅助系统（Medical Diagnosis Assistant） |
| 版本 | V1.2 |
| 文档作者 | 杨晴晴（产品 / 项目负责人） |
| 更新日期 | 2026-09 |
| 定位 | 面向患者自查与基层医生辅助的"症状 → 诊断建议"智能工具 |

---

## 1. 背景与问题

- **用户痛点**：普通用户身体不适时，缺乏可靠、快速、可解释的初步判断途径；去医院前不了解该挂什么科、哪些症状需要警惕。
- **医生痛点**：基层门诊重复性问诊多、病历信息结构化程度低，人工整理症状耗时长。
- **机会**：UMLS 医学知识库 + 机器学习已经可以把"症状组合 → 可能疾病 + 概率 + 相关症状"做成可解释的自动化流程，成本低、可私有化部署。

## 2. 目标与非目标

**产品目标**
1. 用户输入症状（中文/英文）后，**一次操作**获得：疾病预测、相关症状建议、疾病详情。
2. 结果**可解释、可追溯**：每个疾病都带概率与相关症状，详情来自标准医学知识库（UMLS）。
3. 提供清晰的免责声明，避免医疗风险。

**非目标（V1 不做）**
- 不做在线问诊、不做处方开具、不做医保/挂号对接。
- 不做多轮对话（V2/V3 规划）。
- 不替代医生诊断。

## 3. 用户与场景

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 普通患者 | 出现头痛、发烧等不适，想先自查 | 快速知道可能是什么病、要不要就医 |
| 基层医生 | 接诊时快速过一遍鉴别诊断 | 疾病列表 + 概率 + 相关症状，辅助决策 |
| 医学生 | 学习症状与疾病关联 | 症状↔疾病知识查询、理解 CUI 体系 |

## 4. 功能需求

### 4.1 一键诊断（V1.2 核心功能）

**流程**：
```
输入症状（中文/英文，逗号或顿号分隔）
  → 症状名标准化（中文映射 + UMLS CUI 匹配）
  → 疾病预测（朴素贝叶斯模型，按概率排序 Top5）
  → 相关症状建议（CUI2Vec 语义相似度）
  → 疾病详情（UMLS 数据库查询）
  → 输出一份完整《诊断报告》
```

**验收标准**
- 输入 1~N 个症状均可运行；识别失败的症状单独提示。
- 报告包含：已识别症状（含 CUI）、疾病预测（疾病名/CUI/概率/相关症状）、相关症状建议、疾病详情、免责声明。

### 4.2 手动模式（保留，供进阶）

- 症状验证：症状名 → CUI。
- 疾病预测：CUI 列表 → 疾病 + 概率。
- 相关症状建议：CUI → 相关症状。
- 疾病详情查询：CUI → UMLS 详情。

### 4.3 非功能需求

| 类别 | 要求 |
| --- | --- |
| 响应速度 | 单次一键诊断 ≤ 15 秒（受模型加载与数据库查询影响） |
| 可用性 | Docker 一键部署；重启后可恢复 |
| 可解释性 | 每个结果可追溯到模型概率或知识库条目 |
| 数据安全 | 纯本地运行，患者数据不上云 |
| 合规 | 页面显著展示"仅供参考，不构成医疗建议" |

## 5. 产品指标（北极星与过程指标）

- **北极星指标**：一键诊断"完整报告生成率"（输入症状后成功产出报告的比例）。
- **过程指标**：
  - 症状识别率（输入症状中能被映射为 CUI 的比例）
  - 预测平均耗时、报告生成耗时
  - 用户操作步数（从输入到结果，V1.2 已从 4 步降为 1 步）
  - 结果点击/复制率（衡量用户认为结果有用）

## 6. 技术方案概览

```
[Gradio 前端] ──HTTP──▶ [Flask 后端]
                          ├─ 症状标准化：en_Labels.js（症状名↔CUI）
                          ├─ 疾病预测：all_mnb.pkl（MultinomialNB 朴素贝叶斯）
                          ├─ 症状相似：10_epochs_0.6_similarity.npy（CUI2Vec 向量 + 余弦相似度）
                          └─ 详情查询：umls.db（UMLS SQLite 知识库）
```

- 预测**不是调用外部大模型 API**，而是本地训练的传统机器学习模型 + 医学知识库（详见《项目分析与复盘》）。
- 模型可解释、零外部 API 费用、可私有化。

## 7. 合规与风险

| 风险 | 应对 |
| --- | --- |
| 医疗误导风险 | 显著免责声明；定位"辅助参考"而非诊断 |
| UMLS 数据授权 | 向 NLM 申请授权，数据库不随仓库分发 |
| 中文症状覆盖不足 | 内置常见症状中文映射，其余引导英文输入 |
| 模型准确率有限 | 展示 Top5 而非唯一结论，突出"可能性排序" |

## 8. 迭代路线

- **V1.0**：后端 5 个 API + Gradio 四标签页手动流程（已上线）。
- **V1.2**：一键诊断，输入症状直达完整报告（已实现）。
- **V2.0（规划）**：接入大语言模型，把"预测 + 推荐 + 详情"升级为**多轮对话式 AI Agent**：
  - 意图识别：区分"自查/挂号建议/解释术语"等意图
  - 工具调用：Agent 自主调用 validateSymptom / predict / sySuggest / getDetails 工具
  - RAG：基于 UMLS 知识库做检索增强回答
- **V3.0（设想）**：接入医生工作台、病历自动生成、随访提醒，形成"诊前-诊中-诊后"闭环。

## 9. 术语表

- **CUI**：UMLS 中每个医学概念的唯一标识符（如 C0018817 = 头痛）。
- **UMLS**：统一医学语言系统，美国国立医学图书馆维护的医学概念知识库。
- **CUI2Vec**：对 CUI 概念做词向量化，用向量相似度衡量症状相关性。
